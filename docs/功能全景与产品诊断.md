# 奕成长课后平台 · 功能全景与产品诊断

> 本文档基于当前代码实现核实整理，覆盖三类登录角色 + 一类隐性角色（家长）的全部已上线功能，并附资深产品经理视角的问题诊断。首个试用机构已于 2026-09-02 上线并产生真实数据。

## 一、角色总览

| 角色 | 登录方式 | 核心职责 | 主要入口 |
|---|---|---|---|
| **机构管理员**（`Role.ADMIN`） | 手机号+密码 | 机构结构管理（教师/班级/课程/学生）、业务功能开关、定价、账单、运营数据只读看板 | 管理后台（4 大分组 8 个模块） |
| **教师**（`Role.TEACHER`） | 手机号+密码 | 托管班日常看板操作、课外课点名消课、花名册维护 | 看板/花名册/消课三个页面，按名下资源动态显示 |
| **平台管理员**（`Role.PLATFORM_ADMIN`） | 手机号+密码 | 开通新机构、查看机构列表（跨机构） | 独立的平台管理页 |
| **家长**（隐性角色） | 无登录，凭令牌链接 | 查看孩子的托管月度表现 *或* 课外课账户（二选一） | 公开分享页，无导航无账号体系 |

> 管理员同时持有「管理员权限」和「教师身份」：没有标注 `@PreAuthorize` 的教师类接口（如建班级），管理员账号一样可以调用——这是当前鉴权模型的设计选择，见诊断 #9。

## 二、机构管理员（ADMIN）

管理后台按侧边栏四个分组组织：**基础设置 / 结构信息 / 运营产出 / 财务**。机构级开关（托管/课外课）会隐藏对应模块入口，但「学生总览」「教师列表」「定价中心」「基础配置」始终可见。

### 基础设置
- **基础配置**（始终可见）：机构信息（名称、Logo）+ 业务功能开关（启用托管/启用课外课）。两开关不能同时关闭。开关只影响前端导航显示，不禁用后端接口（见诊断 #7）。

### 结构信息
- **教师列表**（始终可见）：建号（可选角色：教师/管理员，默认教师）、查看管理的班级（点击可跳转只读看班）、改名、删除（含影响评估：全部删除/转移给其他教师）。
- **托管班级**（`custodyEnabled=false` 隐藏）：重命名、改派教师、删除。**没有新建入口**——建班由教师自助完成。
- **课程管理**（`offCampusEnabled=false` 隐藏）：创建课程（名称+时长+**必须指定教师**）、改派、设价、停用/启用。**只能管理员创建**，教师无自建入口。
- **学生总览**（始终可见）：全机构学生统一列表，含身份徽标（托管/纯课外课）、课外课报名情况。唯一能同时看到学生「托管+课外课」全貌的界面。纯课外课学生才有「对账单/充值」按钮。

### 运营产出
- **任务完成情况**（`custodyEnabled=false` 隐藏）：按日期/班级查看学生数、签到数、任务完成数。

### 财务
- **定价中心**（始终可见）：**目前只有托管定价**（学费+餐费），课外课单价仍留在「课程管理」里（见诊断 #4）。
- **账单管理**（`custodyEnabled=false` 隐藏）：按班级+月份查看账单、标记已付/未付、查看明细（含课外课消课自动生成的附加费行）。**按班级组织，纯课外课学生不会出现**（见诊断 #3）。

## 三、教师（TEACHER）

导航完全取决于名下实际资源：

- 有托管班 → 显示「花名册」；无则隐藏，看板提示「暂无托管班」。
- 有课外课 → 显示「消课」；无则隐藏。
- **两者都没有** → 整页替换为空状态，提示联系管理员或自助建班。

功能：
- **托管看板**：自建班级（无需审批）、花名册维护、任务模板布置（支持归档非硬删）、单个加任务会**自动同步给同学籍班其他学生**、打卡签到、放学确认。
- **课外课点名消课**：选课程+日期（默认今天）→ 花名册勾选出勤（默认全勾）→ 批量确认。已消课学生静默跳过不重复扣费；未勾选学生不生成任何记录（无请假概念）；**消课前不校验余额**（见诊断 #1）。

## 四、平台管理员（PLATFORM_ADMIN）

- **机构开通与列表**：一次性创建机构+该机构首个 ADMIN 账号，初始密码明文展示一次；列表展示教师数/创建时间。

## 五、家长（隐性角色）

- **公开分享页**：头像/姓名/学籍班 + 二选一内容：
  - 有托管班 → 月度统计（完成/未完成天数、每日任务完成率、平均评分、到校时间）。
  - 无托管班（纯课外课）→ 消课账户对账单（已充值/已消耗/余额）。
  - **互斥展示**：若学生两者都有，只显示托管统计，看不到课外课情况（见诊断 #6）。

## 六、产品诊断：9 项值得关注的设计问题

按业务/财务风险优先排序。

### #01 · 高风险 — 课外课消课完全不校验余额 ✅ 已修复（2026-10-03）
**现象**：系统有「充值」和「消课」概念，但消课时从不检查余额，哪怕余额为负也能继续，唯一反馈是对账单上的负数。
**影响**：点名默认全勾，容易在未提醒续费时持续产生「欠课时」，只能靠人工翻账单发现。
**建议**：消课前读取余额，不足时至少在点名界面标红提示，严格场景可配置阻断。
**代码**：`course/service/CourseConsumptionService.java:74` `recordBatchConsumption`（无余额检查）；`CourseAccountService.java:62` `getStatement`（余额仅用于展示）。
**已做**：`listRosterForCourse` 新增按课程计算的 `balance`（仅纯课外课学生，托管学生恒为 null），`CourseConsumptionPage.tsx` 点名列表里余额 ≤0 标红提示，不阻断消课（按用户决策，暂不做阻断开关）。

### #02 · 高风险 — 同一动作，三套互不相通的财务处理（短期缓解已做，架构统一未做）
**现象**：「确认上了一节课外课」的财务处理完全取决于该生是否同时在托管班：无托管班→预充值/余额模式，无正式账单；有托管班→无预充值，费用月底自动追加进托管账单附加费。
**影响**：财务人员要理解两套规则，同类学生收费体验不一致，容易引发核账混乱和家长困惑。
**建议**：短期在课程详情页标注两种计费模式；中长期考虑统一为「记录到课+月度账单」，预充值仅作为支付方式而非独立核算体系。
**代码**：`CourseAccountService.java:47` `recharge`（有班级时抛 `RechargeNotAllowedException`）；`BillGenerationService.java:105` `computeCourseConsumptionRows`。
**已做（短期缓解）**：`CourseConsumptionPage.tsx` 点名花名册的身份徽标从「托管/纯课外」改为「托管（计入月度账单）/纯课外（扣课时余额）」，明确标注实际财务处理。中长期的架构统一仍未做。

### #03 · 高风险 — 纯课外课学生在「账单管理」完全不可见 ✅ 已修复（教学单元合并时顺带解决）
**现象**：账单管理严格按托管班组织，纯课外课学生没有班级，结构性地不会出现。唯一入口是「学生总览」操作列的按钮。
**影响**：月度财务核对时容易完全遗漏这部分学生的欠费风险，尤其叠加 #01 后更隐蔽。
**建议**：在账单管理页顶部增加「纯课外课学生」分区，至少汇总展示余额异常学生。
**代码**：`AdminBillingModule.tsx`（按班级分组）；`AdminStudentsModule.tsx`（按钮仅对 `offCampusOnly` 展示）。
**已做**：托管班+课外课合并为统一教学单元模型后，`BillGenerationService.generateBill` 不再因缺少班级 404，`getBillOverview`/`getBillOverviewAllMonths` 改为遍历全部学生，纯课外课学生自然出现（学费/餐费记 0，只汇总课外课消课附加费）。

### #04 · 中 — 「定价中心」名不副实 ✅ 已修复（2026-10-03）
**现象**：定价中心只有托管定价一张卡片，课外课单价仍在「课程管理」的「设置单价」里。
**影响**：管理员以为能统一调价，实际漏了课外课，命名与实际能力不符。
**建议**：把课外课单价表迁入定价中心，或改名为「托管定价」以符合实际范围。
**代码**：`AdminPricingModule.tsx`（222 行，仅托管定价卡片）；`AdminCoursesModule.tsx`（设置单价按钮仍在此）。
**已做**：`AdminPricingModule.tsx` 新增「课外课定价」分区，复用 `/admin/teaching-units?billingMode=LESSON_COUNT` 列出全部课外课并可编辑单价；原「教学单元管理」页课外课 Tab 的「设置单价」入口移除，改为只读展示 + 「在定价中心设置」提示，统一入口。

### #05 · 中 — 班级 vs 课程：两个相似实体，治理方式完全相反 ✅ 已修复（教学单元合并时解决）
**现象**：托管班级只能教师自建，管理员不能新建；课外课程只能管理员建且必须指定教师，教师无自建入口。
**影响**：两个业务上相似的「教学单元」权限模型完全反转，增加培训/理解成本。
**建议**：若有刻意的业务考虑应显性说明；若无特殊考虑，可让管理员也能建班级。
**代码**：`AdminClassRoomController.java`（仅 GET/PATCH/DELETE，无 POST）；`AdminCourseController.java:34`（POST，教师 id 必填）。
**已做**：托管班+课外课合并为统一 `AdminTeachingUnitController`，建班/建课/改派/启停/删除统一收归管理员（`@PreAuthorize("hasRole('ADMIN')")`），教师自建班级/学生入口（`POST /api/classes`、`POST /api/classes/{id}/students`、课外课自建+报名）已硬下线。

### #06 · 中 — 家长分享链接：托管统计与课外课账单互斥展示
**现象**：分享页只按「是否有托管班」二选一，双重身份学生的家长看不到课外课情况。
**影响**：削弱分享链接作为「家校沟通自助入口」的完整性。
**建议**：改为「有则都展示」，两类内容作为独立卡片按实际数据展示。
**代码**：`PublicShareService.java:30` `getShare` → 行 35 `classRoomId == null` 分支。

### #07 · 中 — 机构功能开关只是「前端软开关」
**现象**：关闭托管/课外课只隐藏导航入口，底层接口无机构级拦截，理论上仍可被直接调用成功。
**影响**：当前风险低，但若未来开放 API 对接，关闭的功能仍可能产生数据，与管理员预期不符。
**建议**：暂不改造，但在内部文档标注「开关是 UI 层面的，非业务硬约束」；接入对外 API 时再补后端校验。
**代码**：`AdminInstitutionService.java` `updateFeatureFlags`（仅校验不能同时为 false）；`AdminSidebar.tsx` `isModuleHidden`（纯前端判断）。

### #08 · 低（设计权衡） — 点名消课没有「缺席」记录，历史不可追溯
**现象**：未勾选学生不生成任何记录，呼应「课外课无请假概念」的简化设计。
**影响**：事后无法区分「教师忘记点名」和「学生确实没来」，费用争议时缺乏依据。
**建议**：暂不建议改动核心逻辑；如投诉增多可加一条轻量操作日志（「本日已点名，共到 N 人」），不改变语义。
**代码**：`CourseConsumptionService.java:74` `recordBatchConsumption`。

### #09 · 低（已验证实现正确） — 管理员的「教师身份」是隐式的
**现象**：管理员的只读看板正确路由到受限只读接口（`adminKanbanApi`，仅 GET，UI 带「只读」徽标，修改按钮全部隐藏）；但管理员同时满足所有未标注 `@PreAuthorize` 的教师接口鉴权条件，理论上可通过其他路径以教师身份操作任意本机构班级。
**影响**：当前 UI 路径设计正确、无实际漏洞，但权限模型依赖「前端不提供入口」而非「后端禁止」，属隐式约定。
**建议**：无需改动，建议在接口文档中备注这一边界，避免未来新增接口产生错误权限假设。
**代码**：`KanbanPage.tsx:99`（`isAdmin` 分支调用 `adminKanbanApi.*`）；`AdminKanbanController.java`（class 级 `@PreAuthorize("hasRole('ADMIN')")`，仅 GET）。
