# 托管班学生学习管理系统 — 项目执行路线图

> 基于 [托管班-PRD-v1.0.md](../../../托管班-PRD-v1.0.md)（2026-08-01）编写。
> 本文档是**高层级路线图**，用于确认阶段划分与优先级；确认后再为具体阶段展开详细工程实施计划（任务级、TDD 步骤）。

**项目性质：** 个人/小团队副业项目，无强制上线截止日期，目标是尽快跑通老师端核心日常流程，拿到 1~2 家机构试用验证。因此路线图按「价值优先、依赖优先」排序，而非按团队并行分工排序。

**技术栈（沿用 PRD 第三节）：**
- 前端：React + Vite + TypeScript + Tailwind CSS
- 后端：Spring Boot（Java），Docker 容器化
- 认证：Spring Security + JWT
- 数据库：MySQL
- 对象存储：MinIO（自建）
- 图片海报：前端本地合成（html2canvas 类方案）

## 阶段 0：项目脚手架与基础设施

**目标：** 建立可运行、可部署的空壳项目，为后续所有阶段提供地基。

**范围：**
- 仓库结构（前后端分仓或 monorepo，待第一次实施时确认）
- 后端 Spring Boot 项目骨架（无业务逻辑），健康检查接口
- 前端 Vite + React + TS + Tailwind 骨架，能访问后端健康检查接口
- Docker Compose：MySQL + MinIO + 后端服务，一键本地启动
- 基础的数据库迁移工具（如 Flyway/Liquibase）接入

**产出物：** `docker compose up` 后，前端页面能显示"后端已连接"之类的联调验证。

**依赖的待确认事项（来自 PRD 第九节）：** 无。

---

## 阶段 1：账号体系与数据隔离

**目标：** 打通"机构 → 老师"的登录与权限隔离，这是后续所有功能的前提。

**范围：**
- 数据模型：Institution、Teacher（账号、所属机构、角色、密码）
- Spring Security + JWT 登录接口、老师首次登录强制改密码
- 数据隔离规则的技术落地：按机构边界过滤所有查询，老师只能看到自己名下数据
- **MVP 补丁：** PRD 明确机构/管理员账号开通方式"留待实现阶段决定"（第九节）。本阶段需要一个**临时的账号创建入口**（如后端种子脚本或未加鉴权保护的内部 API），先手动开通 1 个机构 + 1~2 个老师账号，用于阶段 2/3 联调，避免卡在"没有管理员 UI 就无法创建老师"的死锁。真正的管理员开通界面在阶段 7 补齐。

**产出物：** 能用一个老师账号登录，拿到 JWT，且这个 JWT 在跨机构越权访问时被正确拒绝。

**关键决策点：** 临时账号创建入口的形式（种子脚本 vs 内部 API）——建议种子脚本，避免留下未鉴权接口的安全隐患。

---

## 阶段 2：任务库与学生名册

**目标：** 老师能维护任务模板和班级学生名单，为阶段 3 的看板提供数据。

**范围：**
- TaskTemplate：机构内共享的增删查，按科目分类
- Class：托管班级读取（创建仍由管理员完成，阶段 7 前用阶段 1 的临时入口手工建班级）
- Student：老师对自己班级的学生增删改（姓名、学校班级、在读状态；头像留到阶段 4）

**产出物：** 老师登录后能看到自己班级的学生名册（暂无头像），能维护一个共享任务库。

---

## 阶段 3：看板核心：任务分配与完成（MVP 主线，最高优先级）

**目标：** 实现 PRD 第七节"典型每日流程"完整闭环，这是产品的核心价值。

**范围：**
- 首页按托管班级 Tab + 学生卡片竖向列表（移动端优先布局）
- 批量分配任务给全班；对个别学生增减常规任务；添加定制任务
- **按学校班级批量同步**逻辑（六.3 最后一条）：单独给学生加任务时，自动同步给托管班级内学校班级相同的其他学生，且老师可单独撤销某个学生的这条任务
- 每日任务从空白开始（不带入前一天）
- 打勾完成 + 卡片颜色规则（绿色已完成印章 / 红色放学未完成 / 默认色），优先级判断逻辑
- 放学按钮（仅影响当前托管班级）

**产出物：** 老师能完整走完"分配任务 → 打勾 → 放学 → 卡片变色"的每日流程，这一步完成后产品已具备最小可用价值，可以考虑先给 1 位老师试用收集反馈，再继续后面的阶段。

**关键决策点（建议在本阶段实施前拍板，否则会返工）：**
- 学生转托管班/退托管的历史数据归属（PRD 第九节建议：保留在产生记录时的班级下，不随迁移）
- 任务模板变更是否影响历史记录（PRD 第九节建议：每日任务保存快照，不引用模板实时状态）—— 这条**必须**在阶段 2/3 的数据模型设计时就落地，否则后续改表成本很高

---

## 阶段 4：头像上传

**目标：** 学生卡片支持拍照/相册上传头像。

**范围：**
- 前端拍照/选图组件
- 后端接收图片、写入 MinIO、返回可访问 URL
- 头像仅登录老师可见的访问控制

**产出物：** 学生卡片能显示已上传头像，无头像时有默认占位图。

**风险提示（来自 PRD 第三节）：** 若老师主要用微信内置浏览器打开链接，拍照/相册权限可能受限，建议本阶段一并做"引导复制链接到系统浏览器打开"的提示文案，不必等到阶段 8。

---

## 阶段 5：评星与分享海报

**目标：** 补齐老师评价学生表现、生成海报分享给家长的能力。

**范围：**
- DailyRating：半星~5星评分组件与存储，选填不强制
- 分享海报：前端 html2canvas 合成（头像 + 当日任务清单 ✅/⬜ + 当日评星），生成后预览、保存图片/系统分享
- 海报视觉样式（配色排版）需要在本阶段前定稿（PRD 第九节待确认事项）

**产出物：** 老师能给学生打星，并一键生成、预览、保存/分享当日海报。

---

## 阶段 6：月度统计页

**目标：** 沉淀的历史数据可视化，支持月度回顾。

**范围：**
- 后端统计聚合接口：本月完成天数/未完成天数、每日完成率、平均评星
- 前端折线图展示完成率趋势
- **口径决策（PRD 第九节，必须在写统计 SQL 前拍板）：** 当天任务列表为空时算"未完成"还是不计入分母

**产出物：** 点击学生卡片统计图标，能看到本月的完成情况和趋势图。

---

## 阶段 7：机构管理员看板

**目标：** 补齐管理员角色，替换阶段 1 的临时账号创建入口，形成正式的机构管理闭环。

**范围：**
- 管理员登录后查看本机构所有老师/班级/学生当日完成情况（具体展现形式待细化，PRD 第九节）
- 管理员创建老师账号、设置初始密码
- 管理员创建托管班级并指定老师

**产出物：** 不再需要种子脚本/临时接口，机构可以完全通过管理员账号自行开通老师和班级。

**说明：** 若试点机构数量很少（1~2 家），也可以选择把本阶段延后到试点结束后再做，先用阶段 1 的临时入口手工代运营——由项目负责人自行决定试点节奏。

---

## 阶段 8：打磨与试点上线

**目标：** 补齐边缘体验，准备真实机构试用。

**范围：**
- 移动端响应式细节走查（真机测试，尤其是微信内置浏览器场景）
- "放学"操作误触的撤销入口（PRD 第九节待确认，建议本阶段拍板并实现，避免老师投诉）
- 试点机构邀测（1~2 家），收集反馈

---

## 尚未覆盖 / 明确排除的内容

- 家长端账号、自动提醒、消息推送对接、机构自助开通、计费订阅模块——均为 PRD 第十节"v1.1+ 候选"，不进入本路线图
- 任务完成度与评星自动关联算法、按科目细分月度统计——PRD 第八节明确非目标
