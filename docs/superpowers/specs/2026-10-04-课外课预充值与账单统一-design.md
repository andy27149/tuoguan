# 课外课预充值与月度账单统一 · 设计文档

**对应诊断：** [`docs/功能全景与产品诊断.md`](../../功能全景与产品诊断.md) #02「同一动作，三套互不相通的财务处理」

**目标：** 消除"同一条消课记录被两套互不知情的记账逻辑各自解读"的问题。纯课外课学生保留预充值余额这套体验（充值、看余额、点名界面标红提示），但月度账单不再对这类学生视而不见——余额覆盖不了的消课会作为真实欠费出现在账单里，管理员能像对待托管班学生一样收款/标记已缴费。

## 一、问题的精确形状

`BillGenerationService.generateBill` 已经对所有学生通用（不区分有没有托管班），`computeCourseConsumptionRows` 会无条件把本月全部消课记录算进 `extraFeeTotal`。与此同时 `CourseAccountService` 维护着一套完全独立的「充值 - 消课 = 余额」账本，只服务纯课外课学生（有托管班的学生被 `recharge` 方法拒绝）。

这两套逻辑读的是**同一张表**（`course_consumption_record`），却从不互相知会：

- 月度账单把每条消课都当作"新发生的应收费用"，不管学生是不是已经靠预充值付过钱了。
- 预充值账本把每条消课都当作"消耗一次余额"，不管这笔钱有没有同时被算进某张账单里收一遍。

结果是纯课外课学生理论上可能被收两遍钱（账单一次、预充值余额扣一次），而管理员端的「费用管理」弹窗（`FeeManagementModal`）又完全没适配过这类学生（无条件请求托管班的计费单价，纯课外课学生传 `null` 直接出错），所以这个重复收费的风险目前还没被触发——只是因为账单管理页对这些学生实际上点不进去。

## 二、核心计算模型：按时间顺序回放，不加状态字段

对某个学生在某门课外课上的全部事件（充值 + 消课），按日期排序后从余额 0 开始回放一遍：

- 充值事件：余额加对应课时数。
- 消课事件：先看当前余额是否 `> 0`——是，这次消课记为「已被预充值覆盖」；不是，记为「未覆盖，需要计入账单」。不论是否覆盖，余额都照常减 1（和现在 `recharged - consumed` 的公式完全一致，只是多记录了每一条消课当时是否被覆盖）。
- 同日的充值和消课：约定充值先处理（避免排序二义性，写进代码注释）。

```java
// com.tuoguan.backend.course.service.CourseAccountService
public record ConsumptionCoverage(CourseConsumptionRecord record, boolean coveredByBalance) { }

public List<ConsumptionCoverage> classifyConsumptions(Long studentId) {
    // 按 teachingUnitId 分组，组内按日期排序回放，返回全部历史消课记录的覆盖判定
}
```

**不加 schema、不写迁移脚本、不需要存量数据回填**——覆盖判定是读时现算的，数据源还是现有两张表（`course_recharge_record`、`course_consumption_record`）。这个模型天然带来三个正确性：

1. **月中补充值能追溯覆盖**：充值发生在某次消课之后、另一次消课之前，只会覆盖后面那次，不会错误覆盖前面已经判定"未覆盖"的那次——这是按时间顺序回放的直接结果，不需要额外写"回溯"逻辑。
2. **连续欠费自然延续**：如果某月账单生成后家长没交钱，余额依旧是负的（因为消课照常扣减），下个月继续全额计入账单——不需要"已出账未结清"这种额外状态位，欠款状态就是"余额持续为负"本身。
3. **有托管班的学生零特殊分支**：这类学生从来充不了值（`CourseAccountService.recharge` 已经在写入时拦截），所以他们的余额恒 `≤ 0`，套用同一个公式算出来的覆盖数永远是 0——和现状"消课全额计入账单附加费"完全一致，不需要 `if (teachingUnitId != null)` 这种判断。

## 三、改动范围

**`CourseAccountService`（`course.service`，新增方法，无需新依赖）**
新增 `classifyConsumptions(Long studentId)`，内部复用现有的 `rechargeRecordDao`/`consumptionRecordDao` 查询。`ConsumptionCoverage` 作为新的共享 DTO，放在 `course.web` 包（和 `CourseBalanceRow` 等现有 DTO 同样的位置约定）。

**`BillGenerationService`（`billing.service`，重写 `computeCourseConsumptionRows`）**
改为调用 `courseAccountService.classifyConsumptions(studentId)`，过滤出「未被覆盖」且落在目标月份内的记录再分组求和。`billing` 包本来就直接依赖 `course` 包的 DAO/领域类型，新增对 `CourseAccountService` 的依赖方向一致，不是新引入的耦合；改完之后 `BillGenerationService` 甚至不再需要直接持有 `CourseConsumptionRecordDao`——"消课到底算不算钱"这件事的唯一权威来源收敛到 `CourseAccountService` 一处。

**`CourseConsumptionSummaryRow`（`admin.web`，加一个字段）**
现有字段 `(courseId, courseName, pricePerLesson, lessonCount, amount)` 中 `lessonCount`/`amount` 的语义收紧为「未覆盖、需要计入账单」的部分；新增 `coveredByBalanceCount`（本月被预充值覆盖掉的消课次数），供前端展示完整拆分。`listCourseConsumptionForMonth`（供 `FeeManagementModal` 读取）和 `generateBill` 内部都改用同一份分类结果，只是前者展示全部拆分、后者只取未覆盖部分去算钱。

**`FeeManagementModal.tsx`（两处修复）**
1. 没有托管班的学生（`classRoomId === null`）跳过「本月托管费金额」输入框和 `fetchClassBillingRate` 调用——现状对这类学生无条件请求会直接出错，这是账单管理页目前点不进纯课外课学生「费用管理」的直接原因。
2. 「课外课消课」只读表格增加覆盖拆分展示：「本月消课 3 次，其中 2 次已用预充值抵扣，1 次需计入账单（¥50）」。

**`AdminStudentsModule.tsx`（学生总览行操作列）**
纯课外课学生那一行补上「费用管理」按钮（现在只有「对账单/充值」），和有托管班的学生一样可以生成/管理月度账单；「对账单/充值」按钮保留，管理预充值不受影响。

**不改动的部分**
- `AdminCourseStatementModal`（对账单/充值）的"剩 X 课时"展示——语义不变，依然是 `recharged - consumed` 的原始余额，只是现在这个余额会在账单生成时被正确地"花出去"而不是被account两次。
- 上一轮已经做的点名界面余额标红（`CourseConsumptionPage.tsx`）——那是教师消课时的即时提示，和本次账单生成逻辑是两个独立的读取路径，互不影响。
- 双身份学生（有托管班又报了课外课）的分享页「课外课情况」卡片——继续展示课程+最近消课日期，不涉及余额/账单概念。

## 四、范围界定（本次明确不做）

- **历史数据不回填**：这次统一只对以后新生成的账单生效。已经生成过的历史账单金额不变；如果管理员以后手动对某个历史月份重新点"生成账单"，会用新逻辑重算并覆盖——这是账单生成本来就有的幂等覆盖行为，不是本次新引入的特性，不需要专门处理或警告。
- **不改变预充值的使用门槛**：谁能充值（只有纯课外课学生）这条规则不变，本次不讨论是否放开给有托管班的学生。
- **不做"欠费提醒"之外的催收机制**：账单生成后是否已缴费依旧是管理员手动标记，不新增自动提醒/通知。

## 五、测试策略

**`CourseAccountService.classifyConsumptions` 单元测试：**
- 全部消课被充值覆盖（余额始终为正）。
- 从未充值，全部消课未覆盖。
- 月初充值只够覆盖一部分，月中消课超出部分应判定未覆盖。
- 月中补充值：覆盖发生在充值之后的消课，不覆盖充值之前已经判定未覆盖的消课。
- 多课程独立：A 课程余额耗尽不影响 B 课程的覆盖判定。
- 有托管班的学生：恒定全部未覆盖（验证零特殊分支的假设成立）。

**集成测试：**
- `AdminStudentBillControllerTest` 新增场景：纯课外课学生部分覆盖时，生成的账单 `extraFeeTotal`/`extraFeeLines` 只反映未覆盖部分的金额和次数。
- `listCourseConsumptionForMonth` 对应测试：返回的 `coveredByBalanceCount` 和未覆盖的 `lessonCount` 加起来等于当月实际消课总数。

**前端测试：**
- `FeeManagementModal.test.tsx`：纯课外课学生渲染时不出现「本月托管费金额」输入框，出现覆盖拆分文案；有托管班学生的现有用例保持不变。
- `AdminStudentsModule.test.tsx`：纯课外课学生行同时渲染「对账单/充值」和「费用管理」两个按钮。
