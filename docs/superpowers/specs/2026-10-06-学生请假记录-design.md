# 学生请假记录搬到教师端 —— 设计文档

## 背景

请假登记目前只在机构后台（管理员）能操作：管理员在"费用管理"弹窗里选一个日期
区间+填一个原因，一次性批量登记多天请假。这个功能应该搬到托管班老师的学生看
板卡片上——老师点"请假"，弹窗填个原因即可，跟现在的用餐记录、到了打卡保持一
致的"每日记录"交互风格，月度账单统计请假天数时直接读老师登记的记录。

## 现状（调研结论）

- `student_leave_record` 表本身已经是按天存一条记录（student_id + leave_date
  唯一），架构上和 `student_meal_record` 完全一样，不需要改表结构。"区间"只存
  在于现有 API 的外壳：`AdminStudentLeaveController` 的
  `POST /api/admin/students/{id}/leave-records` 接收 `{startDate, endDate,
  reason}`，`BillGenerationService.registerLeaveRange()` 内部循环逐天
  `dao.upsert()`，本质上还是在插多条单日记录。
- 请假登记入口只有管理员角色能用（`@PreAuthorize("hasRole('ADMIN')")`），界面
  在 `FeeManagementModal.tsx` 的"请假管理"区块：区间选择器 + 原因输入 + 当月请
  假日期 chip 列表（可逐条点 × 取消）。
- 账单里"请假天数"目前只存一个汇总数字 `leave_days =
  countByStudentIdAndDateRange(...)`，没有像课外课费用、刚做完的用餐记录那样
  拍一份"具体哪几天"的快照——账单生成之后，哪怕老师后续改了请假记录，账单上
  的汇总数字也不会跟着变（因为是生成时算好存死的 `leave_days` 字段），但没有
  明细可查，跟用户这次要求的"账单明确展示哪天请假"还有差距。

## 核心设计决策

1. **请假记录只能标记"今天"**：和用餐记录、到了打卡的设计保持一致，不做历史
   日期回看/批量登记未来几天的入口。原来管理员能登记未来区间的能力这里不保
   留——这是本次讨论中明确确认过的取舍。
2. **管理员后台完全不保留请假相关入口**：不管是写（区间登记）还是读（实时查
   看谁今天请假）都不留，`FeeManagementModal` 的"请假管理"区块整块删除。管理
   员只能在生成好的月度账单详情里看到最终的请假天数、具体日期和原因，跟现在
   用餐记录在账单里的展示方式一致——这也是本次讨论中明确确认过的取舍。
3. **账单一旦生成就固定，请假明细也要快照**：新增 `monthly_bill_leave_line`
   子表，生成账单时把"这个月具体哪几天请假+原因"拍成快照存进去，用法完全比
   照刚做完的 `monthly_bill_meal_line`。
4. **请假需要填写原因，所以交互上不能是纯瞬时切换**：用餐/到了的"设置"动作可
   以不弹窗直接完成，但请假必须填原因，所以不管是首次标记还是修改已有记录，
   点击「请假」按钮都会打开一个弹窗（参照 `ArrivalModal` 的结构，把"时间输入"
   换成"原因输入框"），弹窗里能保存、能清除（已请假时才显示"清除请假"按钮）。

## 数据模型

```sql
-- monthly_bill_leave_line：生成账单时把本月实际请假的具体日期+原因拍成快照，
-- 完全比照 monthly_bill_meal_line。
CREATE TABLE monthly_bill_leave_line (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    monthly_bill_id BIGINT NOT NULL,
    leave_date DATE NOT NULL,
    reason VARCHAR(255),
    CONSTRAINT fk_monthly_bill_leave_line_bill FOREIGN KEY (monthly_bill_id) REFERENCES monthly_bill(id) ON DELETE CASCADE
);
```

`student_leave_record` 表结构不变。下一个可用的 Flyway 版本号是 V24。

## 后端改动范围

- 新增 `kanban/web/StudentLeaveRecordController`（教师端，完全比照
  `StudentMealRecordController` 的形状）：
  - `GET /api/classes/{classId}/leaves?date=` → `[{studentId, reason}]`
  - `PATCH /api/students/{studentId}/leave`，body `{date, reason}` → upsert
  - `DELETE /api/students/{studentId}/leave?date=` → 清除
  - 鉴权复用 `ClassRoomService.getOwnedByTeacher`。
- 复用现有 `StudentLeaveRecordDao`（已有 upsert/clear 单日方法，不用新建，
  `registerLeaveRange` 循环调用的也是它），只是新增一个 Service 方法给教师端
  controller 用，保持和 `StudentMealRecordService` 一致的鉴权风格。
- 删除 `AdminStudentLeaveController` 现有的写接口
  （`registerLeaveRange`/`cancelLeave` 对应的 HTTP 方法），因为管理员不再需要
  登记请假的入口。
- 新增 `billing/domain/MonthlyBillLeaveLine`、
  `billing/dao/MonthlyBillLeaveLineDao` + `JdbcMonthlyBillLeaveLineDao`，完全
  比照 meal line 的 DAO。
- `BillGenerationService.generateBill()`：
  - 把 `leaveDays = dao.countByStudentIdAndDateRange(...)` 换成先查出请假记录
    列表，`leaveDays = list.size()`。
  - 把查到的 `(日期, 原因)` 列表 insert 进 `monthly_bill_leave_line`。
  - `MonthlyBill` 新增字段，比如 `List<BillLeaveLine> leaveLines`
    （`BillLeaveLine(LocalDate date, String reason)`），`enrich()` 读回。
- 教学单元/教师删除的级联清理（`AdminTeachingUnitService.delete()`、
  `AdminTeacherService.deleteTeacher()`）里已经有
  `studentLeaveRecordDao.deleteAllByTeachingUnitId(...)`（请假记录本身的清理，
  这次不用动），只需要确认账单侧的 `monthlyBillLeaveLineDao.deleteAllByBillId`
  在账单重新生成/删除时也被调用，和 meal line 的处理方式一致。

## 前端改动范围

- 新增 `frontend/src/api/leave.ts`：
  ```ts
  export interface StudentLeaveRecord { studentId: number; reason: string | null }
  fetchLeaves(classId, date)
  setLeave(studentId, date, reason)   // PATCH
  clearLeave(studentId, date)         // DELETE
  ```
  不新增 admin 侧的只读 mirror（按本次讨论的决定，管理员不需要实时看）。
- 新增 `LeaveModal.tsx`（仿照 `ArrivalModal.tsx`）：原因输入框（必填）+ 保存 +
  取消 + 清除请假（仅已请假时显示）。
- `StudentCard.tsx`：新增 `leaveReason: string`（空字符串=未请假，哨兵值风格
  同 `arrivedAt`）、`onSetLeave?`、`onClearLeave?`。按钮文案：未请假"请假"／
  已请假"已请假"，不管哪种状态点击都打开 `LeaveModal`。只在非 `readOnly`
  （老师视角）渲染这一行，`readOnly` 模式下完全不展示（管理员不该看到实时状
  态）。
- `KanbanPage.tsx`：新增 `leaveByStudent: Map<number, string>` 状态，教师分支
  调 `leaveApi.fetchLeaves`，管理员分支用一个 `Promise.resolve([])` 占位保持
  `Promise.all` 两边解构形状一致；新增 `handleSetLeave`/`handleClearLeave`，
  乐观更新+失败回滚，模式同 `handleSetArrival`/`handleClearArrival`。
- `BillDetailModal.tsx`：在用餐日期区块旁边加一个"请假日期（共N天）"区块，每
  行展示日期+原因，比如 `2026-10-03 · 发烧`。
- `api/billing.ts`：`MonthlyBill` 类型新增 `leaveLines: { date: string;
  reason: string | null }[]`；删除不再使用的
  `fetchStudentLeaveRecords`/`registerStudentLeaveRange`/`cancelStudentLeave`。
- `FeeManagementModal.tsx`：删除整个"请假管理"区块（区间选择器+原因输入+当
  月请假日期 chip 列表），"学费覆盖"和只读的"消课记录"表格不动。

## 范围界定 / 不做

- 不支持老师登记非今天的请假（过去补登/未来预登）——这是本次讨论中明确确认
  的取舍，以后如果要支持"老师提前知道孩子下周请假"这种场景，需要单独评估。
- 管理员后台不保留任何请假相关的读/写入口，包括看板只读镜像——这是本次讨论
  中明确确认的取舍。
- 不改动 `student_leave_record` 表结构和已有的单日 upsert/clear DAO 方法，只
  是把调用方从管理员区间接口换成教师单日接口。
- 不改动出勤天数（`attendanceDays`）相关的任何计算逻辑，这次只改"请假天数怎
  么来、账单里怎么展示明细"。
