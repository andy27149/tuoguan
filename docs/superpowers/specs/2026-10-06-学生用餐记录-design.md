# 学生用餐记录 —— 设计文档

## 背景

托管班老师希望能记录每个在读孩子每天的用餐情况。记录之后，后台应该自动把这个
记录换算成餐费，月度账单生成时自动累加；账单上要能明确看到某个学生这个月具体
是哪几天用餐的。

## 现状（调研结论）

- 餐费目前的算法是 `mealAmount = 每日餐费 × 实际出勤天数`，而"实际出勤天数" =
  本月工作日数 − 请假天数，是纯推算值，不依赖任何"孩子今天真的来了/吃了"的逐
  日记录。只要没请假，默认当天出勤、默认收这天餐费。
- 教师看板现有的"到了"打卡（`student_arrival_checkin` 表）跟账单计算完全没有
  关联，纯粹是看板上的展示功能。
- 教师看板整体是"只看今天"的设计：到了、评星、任务都没有回看/修改历史某天的
  入口。要查看历史，走的是"月度统计"弹窗里的日历，但那是纯只读的展示视图。
- 账单（`monthly_bill`）里，"请假"只存了一个汇总数字 `leave_days`，没有快照
  具体请假日期；而"课外课费用"走的是 `monthly_bill_extra_fee_line` 子表，生
  成账单时把明细拍成快照，之后不随教师端数据变动而改变。

## 核心设计决策

1. **餐费计算方式彻底改变**：不再按出勤天数推算，改成 `mealAmount = 每日餐费
   × 本月实际用餐记录天数`。出勤（`totalWeekdays`/`leaveDays`/`attendanceDays`）
   继续保留展示，但不再驱动餐费计算——出勤和用餐是两件独立的事。
2. **账单一旦生成就固定**：生成账单时把"这个月具体哪几天用餐"拍成快照存进新
   建的子表。之后老师改动原始用餐记录，不会让已生成的账单跟着变；管理员需要
   手动点"重新生成"才会用上最新记录。这跟现有课外课费用明细的处理方式一致。
3. **用餐记录只能标记"今天"**：跟教师看板其他每日字段（到了/评星/任务）保持
   一致，v1 不做历史日期回看修改的入口。忘记标记的一天，生成账单时自然不计
   入——这也是"账单一旦生成就固定、需要手动重新生成"的实际意义所在。
4. **用餐记录不要求班级必须先配置餐费**：老师该记就记，是否配置了单价只在生
   成账单那一刻才有意义，跟请假/到了现在的逻辑一致，不在记录环节设卡。
5. **不做批量操作**：先做单个学生卡片上的记录入口，批量（类似"放学"）以后
   再评估。

## 数据模型

```sql
-- 老师每天标记某个学生是否用餐，存在即吃了，删除即撤销，跟 student_arrival_checkin
-- / student_leave_record 的设计风格一致。
CREATE TABLE student_meal_record (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    institution_id BIGINT NOT NULL,
    teaching_unit_id BIGINT NOT NULL,
    student_id BIGINT NOT NULL,
    meal_date DATE NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (student_id, meal_date),
    CONSTRAINT fk_student_meal_record_institution FOREIGN KEY (institution_id) REFERENCES institution(id),
    CONSTRAINT fk_student_meal_record_teaching_unit FOREIGN KEY (teaching_unit_id) REFERENCES teaching_unit(id),
    CONSTRAINT fk_student_meal_record_student FOREIGN KEY (student_id) REFERENCES student(id)
);

-- 生成账单时，把本月实际用餐的具体日期拍成快照，仿照 monthly_bill_extra_fee_line。
CREATE TABLE monthly_bill_meal_line (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    monthly_bill_id BIGINT NOT NULL,
    meal_date DATE NOT NULL,
    CONSTRAINT fk_monthly_bill_meal_line_bill FOREIGN KEY (monthly_bill_id) REFERENCES monthly_bill(id) ON DELETE CASCADE
);
```

下一个可用的 Flyway 版本号是 V23。

## 后端改动范围

- 新增 `kanban/domain/StudentMealRecord`、`kanban/dao/StudentMealRecordDao` +
  `JdbcStudentMealRecordDao`（参考 `StudentArrivalCheckinDao` 的方法形状：按
  teaching_unit_id+date 查一整天的、按 student_id+date 增删单条）。
- 新增 `kanban/service/StudentMealRecordService`：`setMeal(teacherId,
  studentId, date)` / `clearMeal(teacherId, studentId, date)`，复用
  `ClassRoomService.getOwnedByTeacher` 做权限校验，风格参照
  `StudentArrivalCheckinService`。
- 新增 `kanban/web/StudentMealRecordController`：
  - `PUT /api/students/{id}/meal/{date}`
  - `DELETE /api/students/{id}/meal/{date}`
- `kanban/web/*`（看板当日数据接口，对应前端 `KanbanPage` 一次性拉取当天所有
  学生的任务/评价/到校数据的那个接口）需要一并返回当天"谁标记了用餐"，参照
  现有 arrival 数据是怎么混进同一个响应里的。
- `BillGenerationService.generateBill`：
  - 新增 `studentMealRecordDao.findAllByStudentIdAndDateRange(studentId,
    start, end)` 查询本月用餐日期列表。
  - `mealAmount = rate.mealRatePerDay() * 用餐天数`（原来的 `attendanceDays`
    不再参与这个计算，但字段本身保留，继续按原逻辑算，继续展示在账单里）。
  - 把查到的用餐日期列表 insert 进 `monthly_bill_meal_line`。
  - `MonthlyBill` 领域对象/响应增加 `mealRecordDates: List<LocalDate>`
    （或等价字段）。

## 前端改动范围

- `StudentCard.tsx`：在"到了"按钮旁边加一个"用餐"按钮。
  - 未标记：按钮文案"用餐"，点击直接标记今天（不弹窗），接口对应
    `PUT /api/students/{id}/meal/{今天}`。
  - 已标记：按钮文案变成"已用餐"（视觉上类似"到了"打卡后的状态），再次点击
    直接取消标记（也不弹窗——这是个随时可逆的日常小操作，不需要像这次会话里
    给高风险操作加的那种确认）。
  - `readOnly` 模式（家长分享页等）下显示成纯文字"今日已用餐"，未标记时不
    显示任何内容，不可点击，参照"到了"按钮在 `readOnly` 下的现有处理。
- `KanbanPage.tsx`：拉取/维护当天"谁用餐了"的状态，参照现有 `arrivalByStudent`
  的状态管理模式（map 维护 + 乐观更新 + 失败回滚）。
- `BillCard.tsx`：
  - 在"应出勤/请假/实际出勤"那一排汇总数字旁边加一个"用餐天数"。
  - 新增一个明细区块，把 `mealRecordDates` 列出来（参照课外课费用明细行的
    展示方式），用来回应"账单中明确展示哪天用餐"这个需求。
- `api/students.ts` 或新建 `api/meal.ts`：新增 `setMeal`/`clearMeal` 调用；
  `api/billing.ts` 的 `MonthlyBill` 类型加 `mealRecordDates` 字段。

## 范围界定 / 不做

- 不支持老师回看并补记/修改历史某天的用餐记录——跟教师看板其他字段的现状
  保持一致，以后如果要做，应该作为"月度统计日历可编辑"这个更大的、跨字段
  的功能统一考虑，不为用餐单独开一个口子。
- 不做批量标记（"全班都用餐了"），以后视机构反馈再评估。
- 不在记录环节校验班级是否已配置餐费——记录和计费解耦。
- 不改动纯课外课学生（`offCampusOnly`）的任何流程——用餐是托管班概念，课外
  课没有"每日餐费"这个计费维度。
