      Teacher teacher = teacherDao.findByPhone(phone)
              .filter(t -> passwordEncoder.matches(rawPassword, t.passwordHash()))

### Task 5 - JWT鉴权过滤器与隔离验收接口（阶段1核心验收点）

- `TeacherPrincipal` record(teacherId, institutionId, role)。
- `JwtAuthenticationFilter extends OncePerRequestFilter`：解析 `Authorization: Bearer <token>`，调用 `JwtService.parseToken`，成功则把 `TeacherPrincipal` 塞进 `UsernamePasswordAuthenticationToken` 设进 `SecurityContextHolder`；解析失败（`JwtException`）则清空 SecurityContext，放行给后续鉴权规则处理（未认证请求最终被 `anyRequest().authenticated()` 拦成 401）。
- `SecurityConfig` **整体重写**为 v2：
  ```java
  http.csrf(csrf -> csrf.disable())
      .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
      .authorizeHttpRequests(auth -> auth
              .requestMatchers("/api/health", "/api/auth/login").permitAll()
              .anyRequest().authenticated())
      .exceptionHandling(handling -> handling
              .authenticationEntryPoint((req, res, ex) -> res.sendError(HttpStatus.UNAUTHORIZED.value())))
      .addFilterBefore(new JwtAuthenticationFilter(jwtService), UsernamePasswordAuthenticationFilter.class);
  ```
- `TeacherController`：`GET /api/teachers/me`，用 `@AuthenticationPrincipal TeacherPrincipal principal` 取值，`TeacherDao.findById(principal.teacherId())` 查完整信息，返回 `TeacherMeResponse(id, phone, institutionId, role)`。
- **这是阶段1的核心验收测试**：`TeacherControllerIsolationTest` —— 机构A、机构B 各建一个老师（`mustChangePassword=false`，避免被 Task 6 加的过滤器挡住），分别登录拿各自 token，用各自 token 调 `/api/teachers/me`，断言返回的 `institutionId`/`phone` 对应各自机构，不可能串号；另测无 token 访问返回 401。手机号段 `138000020xx`。

### Task 6 - 强制改密

- `ChangePasswordRequest` record(oldPassword, newPassword)。
- `AuthService` **新增方法**：
  ```java
  public void changePassword(Long teacherId, String oldPassword, String newPassword) {
      Teacher teacher = teacherDao.findById(teacherId)
              .orElseThrow(() -> new IllegalStateException("Authenticated teacher not found: " + teacherId));
      if (!passwordEncoder.matches(oldPassword, teacher.passwordHash())) {
          throw new BadCredentialsException("Old password does not match");
      }
      teacherDao.updatePassword(teacherId, passwordEncoder.encode(newPassword));
  }
  ```
- `AuthController` **新增端点**：`POST /api/auth/change-password`，用 `@AuthenticationPrincipal TeacherPrincipal`，catch `BadCredentialsException` 转 401，成功返回 204。
- `MustChangePasswordFilter extends OncePerRequestFilter`：
  - **关键设计点**：`mustChangePassword` **不在 JWT claims 里**（它是登录后可变的字段），所以过滤器不能从 `TeacherPrincipal` 读，必须**注入 `TeacherDao`，按 `principal.teacherId()` 实时查库**判断。
  - 逻辑：`SecurityContextHolder` 里有 `TeacherPrincipal` 且请求路径不是 `/api/auth/change-password` 时，查库；若 `mustChangePassword=true`，返回 `403` + `{"error":"MUST_CHANGE_PASSWORD"}` 并短路；否则放行。
- **SecurityConfig 整体重写为 v3（这里修复了此前 sub-agent 草稿里发现但没来得及修的 bug）**：
  - Bug 原状：Task 6 的草稿版本丢了 Task 5 的 `exceptionHandling` 401 覆盖块，还把依赖注入方式从 `@Bean` 参数注入改成了构造器字段注入，会导致本来预期 401 的测试静默退化成 403。
  - 修复后的最终版本：
    ```java
    @Configuration
    @EnableWebSecurity
    public class SecurityConfig {
        private final JwtService jwtService;
        private final TeacherDao teacherDao;

        public SecurityConfig(JwtService jwtService, TeacherDao teacherDao) {
            this.jwtService = jwtService;
            this.teacherDao = teacherDao;
        }

        @Bean
        public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
            http.csrf(csrf -> csrf.disable())
                .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .authorizeHttpRequests(auth -> auth
                        .requestMatchers("/api/health", "/api/auth/login").permitAll()
                        .anyRequest().authenticated())
                .exceptionHandling(handling -> handling
                        .authenticationEntryPoint((req, res, ex) -> res.sendError(HttpStatus.UNAUTHORIZED.value())))
                .addFilterBefore(new JwtAuthenticationFilter(jwtService), UsernamePasswordAuthenticationFilter.class)
                .addFilterAfter(new MustChangePasswordFilter(teacherDao), JwtAuthenticationFilter.class);
            return http.build();
        }
    }
    ```
- 集成测试 `ChangePasswordFlowTest`：`mustChangePassword=true` 的老师登录后访问 `/api/teachers/me` 得 403 + `MUST_CHANGE_PASSWORD`；改密成功后同一 token 再访问变 200；旧密码错误时改密请求返回 401。手机号段 `138000040xx`。

### Task 7 - 种子命令

- 此前发现的问题：设计文档要求 `--seed --seed.institution= --seed.phone= --seed.password=` 参数格式、创建 **ADMIN** 角色老师；而之前 sub-agent 草稿硬编码固定演示数据、创建的是 **TEACHER** 角色。**这次重新设计严格按设计文档来，不再有偏差。**

- `SeedCommandLineRunner implements CommandLineRunner`：
  ```java
  @Override
  public void run(String... args) throws Exception {
      if (Arrays.stream(args).noneMatch(arg -> arg.equals("--seed"))) return;
      String institution = requireArg(args, "--seed.institution=");
      String phone = requireArg(args, "--seed.phone=");
      String password = requireArg(args, "--seed.password=");
      seedService.seed(institution, phone, password);
  }
  ```
  `requireArg` 从 `args` 里找以指定前缀开头的项，截取后半段，为空则抛 `IllegalArgumentException`。
- 测试：`SeedServiceTest`（继承 `IntegrationTestBase`，手机号段 `138000050xx`）验证建号成功、重复手机号报错；`SeedCommandLineRunnerTest`（纯单元测试，Mockito mock `SeedService`）验证无 `--seed` 时不调用、有 `--seed` 时正确解析参数调用、缺参数时抛异常。
