## 给未来做改动的我自己的提示

1. 先看本索引判断要去哪篇文档，而不是打开项目乱翻。
2. 业务架构/流程文档里提到的页面文件名、服务类名是**指路用的精确指针**，真正要改代码时再去读那个具体文件，不要假设文档里的描述是最新的实现细节——文档描述业务语义，代码才是事实来源。
3. 如果发现文档和代码对不上，优先相信代码，并顺手更新文档（哪怕只改一行），避免文档像 `功能全景与产品诊断.md` 一样再次过时而不自知。
4. **`docs/training/操作培训手册.html` 和 `frontend/src/components/HelpModal.tsx` 是刻意的双处维护**（2026-10-12 决策）：前者是完整版（含截图），给外部/离线分享用；后者是应用内嵌的轻量文字版（不含截图，用户已经在看真实界面），给已登录用户随时点开用。只要改动涉及登录流程、机构搭建步骤、托管看板操作、课外课消课规则、账单计费规则这类训练手册里讲过的内容，**两处都要检查**，不要只改一处就以为完事——这类"用户会被教错"的文档滞后，比普通的文档过期更容易造成实际损害。
