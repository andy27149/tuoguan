## 流程一：机构开通与生命周期

**参与角色**：平台管理员 → 机构管理员
**涉及页面**：`PlatformAdminPage.tsx`

1. 平台管理员在"开通新机构"表单填写机构名称、管理员手机号/初始密码、联系人姓名/电话、地址、试用到期日（默认建议今天+30天）。
2. 提交后系统一次性创建机构 + 该机构首个 ADMIN 账号，初始密码在页面上**明文展示一次**，平台管理员需要立即转告该机构管理员（`mustChangePassword` 已置位，首次登录会强制改密）。
3. 机构进入试用期，状态徽标为"有效至 YYYY-MM-DD"（绿色）。
4. 到期前 7 天内，机构列表该行状态自动变为"N天后到期"（橙色，`EXPIRING_SOON`）。
5. 平台管理员联系机构后，点击"续费"→ 选套餐（试用/月付/半年付/年付）→ 系统按套餐建议新到期日（可手动改）→ 保存，机构 `validUntil` 更新，状态恢复绿色，历史续费记录可随时查看。
6. 若未续费，到期当天后状态变为"已过期N天"（红色，`EXPIRED`）。**到期不会自动封禁任何功能**，纯粹是平台管理员侧的可见提醒，机构仍可正常使用系统。

## 流程二：机构内部搭建

**参与角色**：机构管理员（班级/课程创建已全部收归管理员，教师没有自建入口）
**涉及页面**：管理后台 → 基础配置 / 教师列表 / 教学单元 / 学生总览

1. **基础配置**：确认/修改机构名称、上传 Logo。机构的托管/课外课两个业务功能默认都是开启的，目前「基础配置」页面上手动切换这两个开关的入口是隐藏的（现阶段接入的机构基本都两个都要用，暂时不需要管理员手动管理）。
2. **建教师**：教师列表页"新增教师"，填手机号/姓名/初始密码，选角色（教师/管理员）。创建成功后初始密码明文展示一次。
3. **建教学单元**：
   - 建托管班：教学单元页"托管班"Tab，填班级名称+指定负责教师。
   - 建课外课：教学单元页"课外课"Tab，填课程名称+时长+单价（可留空后续在定价中心补）+指定负责教师（必填）。
4. **建学生**：学生总览页"新建学生"，填姓名+学籍班，可选挂一个托管班（留空=纯课外课学生），可多选报名若干课外课（形成双重身份）。建号时系统自动生成该生的 `shareToken`，分享链接/海报从此可用。
5. **配置定价**（为后续账单生成做准备，见流程五）：定价中心设置托管学费+餐费（支持批量套用到全部班级），以及各课外课单价。

## 流程三：托管班日常运营

**参与角色**：教师（管理员可只读查看，权限细节见[业务架构 · 二、角色体系](./业务架构.md#二角色体系)）
**涉及页面**：`KanbanPage.tsx`

1. 托管班只能由机构管理员在「教学单元」里创建并指定负责教师——教师没有自建入口，若名下还没有托管班，需要联系管理员帮忙建班并分配给自己。
2. **布置任务**：可以从任务库批量分配给全班或单个学生，也可以给单个学生临时加一条任务——加给某学生的任务会**自动同步给其同学籍班的其他学生**，避免逐个重复录入。
3. 每天对每个学生操作：
   - 到校打卡（记录到达时间）。
   - 任务逐项打勾完成/取消完成，也可"一键完成今日任务"批量处理。
   - 给当天表现评 1-5 星，可配一句点评。
   - 用餐登记（是否用餐）、请假登记（填请假原因）——二者互斥于同一天的"正常出勤"语义，但系统不强制互斥，只是业务上通常不会同一天既用餐又请假。
   - 放学确认（标记已放学）。
4. 月底这些逐日数据会被月度统计服务（`MonthlyStatsService`）按月汇总，供家长分享页和管理后台"任务完成情况"模块展示；请假记录额外会被账单生成服务读取用于学费扣减（见流程五）。

## 流程四：课外课点名消课

**参与角色**：教师
**涉及页面**：`CourseConsumptionPage.tsx`

1. 选择课程 Tab（一个教师可能同时带多门课外课），选择上课日期（默认今天，**不允许选未来日期**）。
2. 花名册默认**全勾出勤**（教师手动取消未到场的学生）；若该课程是纯课外课（非托管）学生，余额 ≤0 或 <3 节时会在花名册标红/标黄提示，但**不会阻断消课**（2026-10 的产品决策：提示但不强制阻断）。
3. 点击"确认消课（N人）"→ 弹出二次确认框："请确认针对N个孩子进行消课处理吗，此操作不可更改？"（因为消课即扣课时，不可逆，2026-10 新增）。
4. 确认后批量生成 `CourseConsumptionRecord`：
   - 已经消过课的学生会被静默跳过，不重复扣费。
   - 未勾选的学生**不生成任何记录**（系统没有"缺席"概念，事后无法区分"忘记点名"和"确实没来"）。
5. **计费规则对所有学生一视同仁**（详见[业务架构 · 五、课外课计费与结算](./业务架构.md#五课外课计费与结算充值覆盖--月度账单兜底)，2026-10-12 更正：此前这里写的"按身份分叉成两条路径"理解有误）：不管是纯课外课学生还是有托管班的双重身份学生，消课时系统都会判断这节课有没有被该生该课程的充值余额覆盖——有覆盖就从余额里扣，当月不会再进账单；没覆盖（没充值或充值不够）则在月底生成账单时，按单价计入该生当月账单的"课外课附加费"一行。纯课外课学生也会生成月度账单，只是学费/餐费固定为 0，只统计这部分未覆盖的课外课费用。

## 流程五：账单生成与收款

**参与角色**：机构管理员
**涉及页面**：`AdminPricingModule.tsx`（定价）→ `AdminBillingModule.tsx`（生成与收款）

1. **前置条件**：该托管班已在定价中心设置了学费（元/月）和餐费（元/天），否则生成账单时会报错提示先配置单价。
2. **生成账单**，两种方式：
   - 单班级生成：账单管理页选班级+月份，点"生成账单"，对该班级当月所有学生逐一计算。
   - 一键生成本月账单（2026-10 新增，2026-10-13 调整生成范围）：范围是账单管理页**当前筛选结果**——按班级筛了、按姓名搜了，就只对列表里当前展示的这些学生批量生成；不筛选就等于一次性对全机构所有学生（含纯课外课学生）生成当月账单。已生成过的账单会被重新计算覆盖，失败的会列出原因。
3. **账单金额计算逻辑**（`BillGenerationService.generateBill`）：
   - 学费：按该班级配置的月学费，若当月有请假记录，按"请假天数/应出勤工作日天数"的比例在学费上扣减（请假具体日期和原因会被快照进 `MonthlyBillLeaveLine`，重新生成账单会覆盖更新）。
   - 餐费：按当月实际用餐天数 × 日餐费计算（用餐具体日期同样快照进 `MonthlyBillMealLine`）。
   - 课外课附加费：该生当月所有"计入托管账单"的课外课消课记录汇总为一行附加费（本月已被预充值覆盖的课程消课不会在这里重复收费）。
   - 纯课外课学生同样会生成月度账单（学费/餐费记 0，只汇总当月未被充值覆盖的课外课附加费，见[业务架构 · 五、课外课计费与结算](./业务架构.md#五课外课计费与结算充值覆盖--月度账单兜底)），账单管理页可以用"纯课外课学生"筛选项单独查看，不会在财务核对时被遗漏。
   - **补充值追溯抵扣**（2026-10-13 新增）：如果学生是先欠了课外课费用、账单生成后管理员才补充值，重新生成这个月的账单时会自动核对这门课现在的整体净余额——补够了这笔应收金额归零，补了一部分则只收差额，消课次数和日期照常展示，只是不再收这笔钱了（详见[业务架构 · 5.1.1](./业务架构.md#511-补充值追溯抵扣2026-10-13-新增产品诊断-54)）。**这个核对只在账单还没标"已缴费"时生效**——已经收过现金的账单重新生成不会被后续充值倒着免单。
4. **收款跟进**：账单管理页可查看每条账单明细，标记"已付/未付"；机构总览页的"账单欠费提醒"卡片汇总全机构欠费情况供管理员一眼看到。

## 流程六：家长触达与查看

**参与角色**：教师/管理员（分享）→ 家长（查看）→ 平台管理员（监控活跃度）
**涉及页面**：教师/管理员侧的"分享链接/海报"入口 → `ParentSharePage.tsx`（家长侧）

1. 学生建号时系统已自动生成 `shareToken`，教师/管理员随时可在学生卡片上获取该生的专属分享链接或生成海报（二维码）。
2. 教师/管理员将链接或海报发给家长（通常是微信群/一对一发送）。
3. 家长无需登录，直接打开链接 `/share/{token}`：
   - 若孩子有托管班：看到月度统计日历，点击某一天可查看当天任务完成情况、评分点评、到达时间、是否用餐、请假原因；若孩子同时报了课外课，当天若有消课记录会在"课外课情况"卡片里展示当天上了什么课（跟随日历选中日期变化，不是固定列表）。
   - 若孩子是纯课外课学生：看到课外课账户对账单（已充值/已消耗/余额，按课程分组）。
4. 每次访问会被记录一条"该学生+当天"去重的查看日志（同一天家长反复刷新/多次打开只算一次），不区分具体是哪个家长打开的。
5. 平台管理员在机构列表的"今日查看"列能看到各机构当天有多少**去重学生数**被家长查看过，作为机构活跃度/分享链接实际被使用程度的参考信号。

## 流程七：平台运营监控

**参与角色**：平台管理员
**涉及页面**：`PlatformAdminPage.tsx`

1. 登录后直接看到跨机构的机构列表：机构名称/学生数/班级数/教师数/今日查看人数/联系人/到期状态。
2. 按到期状态优先排查（已过期 → 即将到期 → 已设置但未到期 → 未设置），决定今天要跟进哪些机构。
3. 联系机构后，要么登记续费（见流程一），要么更新联系人信息（如联系人换人、电话变更）。
4. 今日查看人数可以作为"这个机构是否在真正使用分享链接功能"的侧面参考，查看量长期为 0 的机构可能需要额外的产品引导。

## 流程八：账号与权限

**参与角色**：机构管理员（创建者）、教师/新管理员（被创建者）

1. 机构管理员在教师列表创建新账号（教师或管理员角色），生成的初始密码明文展示一次。
2. 新账号首次登录时，后端返回 `mustChangePassword=true`，前端整页替换为改密页面（`ChangePasswordPage.tsx`），**改密完成前无法访问系统任何其他功能**。
3. 改密成功后正常进入系统：
   - 角色为 TEACHER → 默认落地托管看板（或课外课消课，取决于名下资源）。
   - 角色为 ADMIN → 默认落地管理后台"机构总览"。
   - 角色为 PLATFORM_ADMIN → 固定落地平台管理页（这个角色的账号目前没有自助创建入口，是平台侧手工插入数据库创建的）。
4. 管理员删除教师账号时，系统先计算"删除影响范围"（该教师名下有多少班级/课程/学生会受影响），管理员选择"全部删除"或"转移给其他教师"两种处理方式之一后才能真正执行删除——这是一个不可逆的高风险操作，有二次确认。
5. **⚠️ 忘记密码无法自助找回**（2026-10-12 核实更正，此前多处文档误写成"管理员可以重置"）：`ChangePasswordPage.tsx` 走的 `POST /api/auth/change-password` 需要提供**旧密码**才能改成新密码，仅适用于首次登录改初始密码这个场景。一旦账号自己设置过密码之后又忘记，全系统没有任何界面能重置——教师列表、平台管理页都没有这个入口，后端也没有对应接口，只能联系技术支持手工处理数据库。
